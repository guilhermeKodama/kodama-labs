# Cerne — brand reference for building the app

**Cerne** is the heartwood of a tree. The product consolidates a person's finances and their company's (PF + PJ) in one ledger, so they can see what really remains and reach financial freedom. Wealth grows the way a trunk does: **one ring a year**. Tagline: *"Patrimônio se faz em anéis."* The repo is `apps/capital` and the package is `@wallex/capital`. The user only ever sees **Cerne**, and the wordmark is written in lowercase: **cerne**.

## 1. Voice

- Portuguese (pt-BR) first; English is the second locale. Every string goes through next-intl (`src/messages/{pt-BR,en}/*.json`).
- Plain, calm and precise, like a good accountant who is also a friend. Short sentence-case labels, no exclamation marks, no hype.
- Name things by what the user does: "+ Nova transação", "Registrar aporte", "Importar extrato". Statuses read like a person would say them: "No ritmo", "Acima do ritmo", "Estourado".

## 2. Mark

A cross-section of a trunk: eccentric growth rings around a **resin core**. The geometry lives in `src/lib/brand.ts`, in three detail levels:

- `MARK_FULL`: 3 rings, for large sizes.
- `MARK_SIMPLE`: 2 rings, for the sidebar and 32px.
- `MARK_TINY`: 1 ring, for the favicon.

In the UI, draw it with `<Mark>` / `<Wordmark>` from `components/cap/logo.tsx`. They use theme tokens, so they follow light and dark. The app icon is sapwood rings and a resin core on heartwood (`APP_ICON`).

Icon files are generated by `scripts/brand-icons.ts` and named in `ICONS`. **New artwork gets new file names, never a `?v=`**, because launchers cache icons by URL.

## 3. Color: warm wood

Light is sapwood paper with charcoal ink; dark is charcoal with sapwood ink. Every color is a `--cap-*` token in `src/app/globals.css`, used through Tailwind utilities (`bg-brand`, `text-fg-2`…) or `var(--cap-*)` in SVG and inline styles. **Never** use Tailwind palette classes or raw hex in components: `no-raw-colors.test.ts` fails on them.

How charts use them:
- **Pick a hue by meaning, not by index.** A single series is cerne (heartwood), never charcoal.
- Gains are musgo, losses are the brand `neg`, alerts are ipê.
- Investment classes always keep the same hue (`CLASS_COLOR`): renda fixa cerne, ações BR argila, FIIs resina, internacional ardósia, cripto ipê, caixa alburno.

**Swatches** (categories, entities, accounts) are `bg-cat-*` in nine colors: casca, jacarandá, musgo, ipê, sálvia, argila, ardósia, resina, urucum. A swatch is **never a status**. Status is always pos, neg, warn or resin.

**Liberdade financeira** draws the plan as a trunk cross-section, with its own `--cap-trunk-*` tokens: wood rings, the heart, future rings dashed, the goal circle in resin.

## 4. Type

| Face | Use |
|---|---|
| **Fraunces**, soft axis (`font-title`) | titles, dialog titles, page headings, wordmark |
| **Geist** (`font-sans`) | interface text |
| **Geist Mono** (`font-mono`, `tabular-nums`) | amounts, dates, anything aligned by digit |

The fonts are vendored in `src/app/fonts/`. Sizes come **only** from the text roles in `src/app/theme.css`: `text-micro` 10, `hint` 10.5, `caption` 11, `label` 11.5, `body-sm`/`button` 12, `body`/`control` 12.5, `body-lg` 13, `title-sm` 14, `title`/`amount` 15, `heading`/`kpi` 17, `display` 22, `hero` 30 (px at "Médio"). For inline styles and charts, use `textRole()`. No `text-[Npx]` and no `fontSize` literals: `no-raw-text-sizes.test.ts` fails on them. The user's text size setting (Pequeno, Médio, Grande) scales every role.

## 5. Shape, density, touch

- **Radii:** buttons and inputs 6px, panels 8px, dialogs 12px, the floating button 16px. Borders are 1px `stroke-1/2/3`. Surfaces are flat and quiet, with no gradients; shadows only on overlays.
- **Desktop density:** controls 26px (`--cap-control-h`), menu rows 28px, table rows 36px.
- **Touch screens** (`pointer: coarse`) get the 44pt / 48dp tap range automatically: controls 40, rows 44–48, button text 14, control text 15. Text fields are at least 16px so iOS does not zoom in.
- **Keyboard hints** (`<Kbd>`) are hidden on touch screens.

## 6. Layout patterns

- A screen is `<Page crumbs controls secondary primary>` (`components/shell/page.tsx`). Do not hand-build headers.
  - **Desktop:** a 46px bar with the breadcrumbs, then the controls, the secondary buttons and the primary button on the right.
  - **Phone (below `md`):** one bar with ☰, the short title and **⋯ "Mais ações"** (the secondaries). Filters go on their own row. The **primary action is the floating button** at the bottom right. It shrinks while scrolling and hides for the bulk bar and the keyboard.
- **Dialogs** (`cap/dialog.tsx`) are centered on desktop and full screen on a phone, with the action row stuck to the bottom (`DialogFooter`). Side panels use `cap/sheet.tsx`.
- **Safe areas:** use `pt-safe` / `pb-safe` / `px-safe` and the `--safe-*` variables. In the installed iOS app (iOS 26 and later) `--safe-top` adds 12pt to clear the system edge blur. Anything that fills the screen uses `h-dvh standalone:h-screen`.
- **Toasts** are an inverted pill at the bottom center with "Desfazer". Every write is undoable.
- **Use the `components/cap/*` primitives**: Btn, Segmented, Select, Combobox, TextInput, Menu, Panel, Kpi, Table, Badge, Callout. Don't restyle them per screen.

## 7. Checklist for a new screen

- [ ] Only tokens and text roles. `pnpm --filter @wallex/capital test` checks colors, text sizes, the palette and the brand.
- [ ] Works in light **and** dark, at 402px wide (phone) and on desktop.
- [ ] pt-BR and en strings, key parity included.
- [ ] Charts use `CHART` / `SERIES` / `CLASS_COLOR` hues by meaning.
- [ ] One primary action through `<Page primary>`, not a hand-made button.
- [ ] The proof video and validation-package rules in `AGENTS.md`.
